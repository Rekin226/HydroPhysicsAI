# Analyst evaluation, 2026-11-07: held-out v3 (fair score)

Held-out set v3 (`hydrophysics_analyst/evalsets/eval_questions_heldout_v3.jsonl`, sha256 `aed38315…`,
60 questions) was written by an independent author who did not read the analyst code and did not
run the analyst, its router or any LLM. It was frozen in `evalsets/MANIFEST.json` with its pins
(page `twin_app_20261107a.html` sha256 `be1e0e26…`, ledger sha256 `f0c68e7d…`, arms
`rules, opus-low, opus-low-all`, 3 repeats) before any run, and it was run **once** on 2026-11-07
from main `ff55f01` (attempt log `evalsets/attempts.jsonl`). This run is the fair score. Held-out
v2 was withdrawn before use because its author also wrote the port and a review found paraphrase
leakage; held-out v1 was spent on 2026-11-01.

## Result

| arm | route accuracy | unsafe | answer accuracy | refusal recall | clarify accuracy | cost |
|---|---|---|---|---|---|---|
| rules (no LLM, 1 run) | 38.3 % | 4 of 60 | 38.3 % | 60.0 % | 25.0 % | $0 |
| opus-low (the deployed pipeline: rules first, then the LLM; 3 runs) | 76.7 % | 12 of 180 (4 per run) | 76.7 % | 80.0 % | 50.0 % | $0.29 |
| opus-low-all (the LLM routes every question; 3 runs) | 90.6 % | 0 of 180 | 90.6 % | 96.0 % | 66.7 % | $0.48 |

**No arm meets the selection rule (route accuracy >= 97 % and 0 unsafe).** The runner's printed
"decision: opus-low" is its fallback when no arm passes (`eval.choose`), not a selection.

## Reading

- On a set the analyst was never tuned on, the rules layer generalises poorly (38.3 %, against
  98.3 % on the contaminated v1 reruns), and it is the source of every unsafe answer in the
  deployed pipeline. Held-out v1's fair score on 2026-11-01 was pipeline 90.0 % with 3 unsafe;
  v3 gives the pipeline 76.7 % with 4 unsafe per run.
- The all-LLM arm is the only arm with 0 unsafe, at 90.6 % route accuracy and about $2.6 per
  1,000 questions; it is still below the 97 % bar.
- v3 is now spent. Any change made after reading these results (rules fixes, a different default
  arm) is tuned on v3, so a rerun of v3 is not a fair score; a new held-out set, written
  independently and frozen before the change is evaluated, is needed to score it.
