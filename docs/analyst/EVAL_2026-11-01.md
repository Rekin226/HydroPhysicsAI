# Twin analyst: routing eval, 2026-11-01

**What is measured.** Whether a plain-language question reaches the right preset with the right
parameters, or the right refusal, or the right clarification. The answer's numbers and sentences
are not scored here: they come from the page, checked by the parity run, and every answer passes
the validator. **Unsafe** means a question whose correct answer is a refusal received a preset
answer instead.

**Selection rule (written before running, plan Task 17).** Choose the cheapest arm with accuracy
≥ 97 % and 0 unsafe answers; otherwise Opus 5.5 at low effort.

**Setup.**
- Bound page: `results/twin/twin_app.html` in dev mode (unbound), because the ledger's
  20261101a page is not built yet (ruling D8). It is the real 2,148-cell page with its own
  classes and 21 townships.
- Model: `claude-opus-5-5`, effort `low`, structured output with an enum-only schema.
- Pipeline repeats use separate call caches, so each repeat is a fresh sample.
- Question sets (synthetic, kept local in `hydrophysics_analyst/data/`, which the data/ rule
  keeps out of git):
  - `eval_questions_v1.jsonl`: 161 questions, 79 zh. The rules parser was tuned on this set.
  - `eval_questions_heldout_v1.jsonl`: 60 questions, 29 zh, written independently without
    seeing v1 or the code. **This is the fair score.**

## Results

| Arm | v1 (tuned) | Held-out (fair) | Cost / 1,000 questions | p50 / p95 latency |
|---|---|---|---|---|
| rules only (an unsure route counts as wrong) | 77.0 %, 0 unsafe | 86.7 %, **1 unsafe** | $0 | 1 / 10 ms |
| **opus-low pipeline** (hard refusals → rules → Opus when unsure) | **96.3 %, 0 unsafe** (3 repeats) | **90.0 %, 3 unsafe** (one question × 3 repeats) | $0.49–0.90 | 4–7 ms / 2.0–2.2 s |
| opus-low-all (Opus for every question not hard-refused) | 92.5 %, 0 unsafe | 87.2 %, 0 unsafe (3 repeats) | $2.35–2.69 | 1.6 / 2.9–3.5 s |

**What the rules decide.** The rules parser and hard refusals decide 73 % (v1) and 83 %
(held-out) of questions alone. The pipeline arm reaches 100 % refusal recall on v1 and 94.7 % on
held-out, and gets presets and parameters right in 99.0 % (v1) and 94.3 % (held-out) of cases.

**Decision: `opus-low` (the default).** No arm met the bar on the held-out set. The pipeline
beats sending every question to the model on accuracy, cost and latency.

## Every attempt

1. **v1, first run.** The pipeline scored 91.9 % with 0 unsafe. A router bug overwrote the LLM's
   refusal and clarification reasons with `disabled`. These were still refusals, so nothing
   unsafe reached a user. Fixed: refusals and clarifications are kept, and an off-page start
   year is out_of_grid in the rules. Tests were added.
2. **Final run.** The numbers in the table above.
3. **Rules bugs.** Three bugs were found by the held-out set and fixed:
   - "How many hectares of fish ponds…" was answered as a head question. This was the unsafe
     item; no withdrawn number was shown, but it answered a different question. Land area is now
     refused with the volumes frame.
   - 比起來 ("compared with") contains 起 and was read as "starting in".
   - 「再加上…」 inside a rail follow-up lost the rail preset.

   The LLM's `no_policy` refusal now becomes the same "which cut?" clarification the rules give.
4. **One post-fix follow-up on the held-out set** (1 repeat). This is **not** a fair score any
   more. Rules: 88.3 %, 0 unsafe. Pipeline: 93.3 %, 0 unsafe, presets and parameters 97.1 %.

## What the remaining misses are

- **Label disagreements, where the model is arguably right.** Asked for a single township's
  water level, the model refuses with `township_head`. That is ruling D3: township head change is
  not offered. The question writers labelled these as `township_internals`, which shows subsidence
  internals and would answer a different quantity. Likewise "Hi" → out_of_domain against a
  labelled `unknown`, and "Is the HSR safe?" with no policy → "choose a policy" against a labelled
  `missing_cut`, now the same clarification.
- **Real misses still open.** A township named only as "斗字頭那個" gets a refusal instead of the
  ambiguous-town clarification. The all-LLM arm sometimes asks for a year that the question gave.
